# Lesson 02 Tasks

## Start by sharing your process

**Share work from the start.** Create a repository with an initial README, then update it as you work. Do not wait until the project is finished. Open a PR after your first changes; use a Draft PR for work in progress.

**Upload the source project.** Include source code, original materials, and files needed to build the project - not just an exported HTML page. Ask AI for the complete project. If one HTML file is the entire source project, upload that file.

## Task 1 Register your GitHub account

**Submit your registration PR before 11 October 2026. This connects your name to your GitHub account so the teacher can invite you to the course organization. It also gives you practice with PRs.**

A pull request (PR) proposes changes to another repository and lets others review and discuss them.

1. Sign in to GitHub. Open Dashboard and click Fork to copy it to your account.
2. In your fork, open Tasks/lesson-02.md. Add one row to the registration table: your real name, GitHub username, and class (optional). Do not change other students' rows.
3. Click Commit changes. Then choose Contribute → Open pull request. The target is the course Dashboard's main branch; the source is the branch containing your edit.
4. Use the title "Register: your name" and click Create pull request. Saving a change in your fork alone is not enough. For corrections, update the same source branch.

Submit the PR by the deadline; it does not need to be merged yet. Check replies and accept the organization invitation when it arrives. Ask AI for help with unfamiliar clicks. Registration is public at this stage; the course plans to make Dashboard private later.

## Task 2 Move your project and collaborate

**Move and rename your repository.** After accepting the invitation, transfer your existing project to the course organization, or create a new one. Use project- followed by a short project name, such as project-physics-map. Ask AI about transfer or renaming; contact the teacher if permissions are missing.

**Identify your team in README.** State what the project does, members' real names and GitHub usernames, and current progress. Update the member list when it changes. The teacher will arrange course members' read access to private project repositories.

**Explore and write in English.** Browse classmates' work, exchange ideas, and consider teaming up. Star interesting repositories to find them later. Write your own project descriptions and notes in English whenever possible.

See [project conventions](../Projects/conventions.md) for details. Project migration and planning are ongoing tasks after you join the organization.

## Task 3 Review your project in plan.md

Create or update plan.md in the root of your own project repository. Use the headings below to review what you have already done. Continue using Markdown, which you explored in the selection task.

**Focus on the first five sections. Write what you understand now; leave other sections blank or mark them "To be added." Keep updating the same file.**

Copy these headings into your own `plan.md`; keep it at the repository root.

### 1 Find a direction

What real need, interest, or experience started the project? How did talking with AI help organize your ideas?

### 2 Research

Which existing work, reusable resources, and professional knowledge did you read? Keep key links and explain what you learned and can use.

### 3 Narrow down

How did you reduce the scope? What specific problem will you address? Give a concrete situation or example.

### 4 Propose a solution

Why could it solve the problem? What value does it add compared with existing approaches? Label untested ideas as assumptions.

### 5 Define a minimal workflow

What stays in the first version, and what can wait? How does the simplest complete workflow produce a meaningful result?

### 6 Build it

What have you built, and how? Link to work or code; identify simulated or prepared parts. Leave blank if not started.

### 7 Feedback and iteration

What real feedback or evidence did you obtain? What will you change or revisit? Leave blank if no feedback yet.

Summarize your own understanding. Read and check AI's findings, then explain what you learned and why it matters. Do not paste long AI answers or chat histories. Use English whenever possible.

## Task 4 Ask and discuss through Issues

**Post questions in the right repository.** An Issue is a discussion thread. Course-wide questions, shared technical problems, and requests for future lessons go in Dashboard. Questions about your own or a classmate's project go in that project repository.

**Mention the teacher when needed.** Choose Issues → New issue. Explain the problem, what you tried, and any useful screenshots or links. Include @qftgtr in the description or a comment if you want the teacher to respond.

**Learn from other discussions.** Read existing Issues before posting. Add your experience to a similar question, suggest an answer, or share an idea. Report what happened after trying the advice.
